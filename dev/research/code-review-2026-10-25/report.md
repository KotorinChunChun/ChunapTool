# ChunapTool コードレビュー・修正記録

レビュー日: 2026-10-24、修正: 2026-10-25。対象: `f0f9a05` / main / v0.1.2公開後。製品コード、テスト、配布スクリプト、文書を静的にレビューし、中程度の2件と既知のCHN-01を修正した。版番号・配布物は変更していない（未リリース）。

## 指摘と対応

|ID|重大度|内容|対応|
|---|---|---|---|
|CR-01|中|管理pipeで`expectedPid`が整数に収まらない（`1.5`、`1e12`など）と`GetInt32`の`FormatException`が捕捉されず、受付ループが終了する。以後、本体からの状態確認・表示・停止と二重起動時の前面化がプロセス終了まで効かない。|修正済み。`TryGetInt32`で解釈し、整数でなければ一致しないPIDとして拒否する。想定外の例外でもループを継続し、連続失敗時は200ms待って再試行する。|
|CR-02|中|スナップ中の`WINDOWPLACEMENT.rcNormalPosition`はスナップ前の位置を返す。Undoは配置の復元だけを行い、完了判定も通常復元位置で比べていたため、スナップ中の状態へ戻すと別の位置へ移動したまま「直前の状態に戻しました」と表示していた。|修正済み。状態取得時に外枠（`GetWindowRect`）を記録し、通常表示へ戻すUndoでは配置の復元後に外枠の位置へ合わせる。通常表示の完了判定は見える矩形の一致とした。最大化への復元は従来どおり通常復元位置で比べる。|
|CHN-01|低|管理要求の読取り上限と応答書込み期限がない（[セキュリティ診断](../security-audit-2026-10-15/report.md)）。|修正済み。1要求を改行までの4096文字に制限し、応答書込みにも接続後2秒の期限を設けた。|
|CR-03|低|起動中の既存インスタンスと実行ファイルのパスが違う（ポータブル版とsetup版の併用など）と、後から起動した側は何も表示せずに終了する。|未対応。|
|CR-04|低|プロセス名の取得方法が一覧（`QueryFullProcessImageName`）とドラッグ選択（`Process.ProcessName + ".exe"`）で異なり、表示がずれる場合がある。|未対応。|
|CR-05|低|WGCのサムネイル撮影で1枚ごとにD3D11デバイスを作り直している。|未対応。|
|CR-06|低|テストがprivateメンバー名をリフレクションで参照している。CIがない。|未対応。|
|CR-07|文書|README・ガイド・ZIP同梱の案内が「v0.1.1」「本体からの正式導入は未対応」のまま。「設定・履歴は保持します」と書かれているが、ChunapToolは設定もUndo履歴も保存しない。手順に作者環境の固定パスが残る。テストプロジェクトの版が0.1.1。|修正済み。|

- `pwsh -File dev/scripts/test.ps1`: 単体27/27成功。管理連携は、停止ガードに加えて次を追加し成功。
