# ChunapTool コードレビュー・修正記録

レビュー日: 2026-10-24、修正: 2026-10-25。対象: `f0f9a05` / main / v0.1.2公開後。製品コード、テスト、配布スクリプト、文書を静的にレビューし、中程度の2件と既知のCHN-01を修正した。続けて、検証中に見つかった表示倍率依存の配置不具合（CR-08）を修正した。版番号・配布物は変更していない（未リリース）。

## 指摘と対応

|ID|重大度|内容|対応|
|---|---|---|---|
|CR-01|中|管理pipeで`expectedPid`が整数に収まらない（`1.5`、`1e12`など）と`GetInt32`の`FormatException`が捕捉されず、受付ループが終了する。以後、本体からの状態確認・表示・停止と二重起動時の前面化がプロセス終了まで効かない。|修正済み。`TryGetInt32`で解釈し、整数でなければ一致しないPIDとして拒否する。想定外の例外でもループを継続し、連続失敗時は200ms待って再試行する。|
|CR-02|中|スナップ中の`WINDOWPLACEMENT.rcNormalPosition`はスナップ前の位置を返す。Undoは配置の復元だけを行い、完了判定も通常復元位置で比べていたため、スナップ中の状態へ戻すと別の位置へ移動したまま「直前の状態に戻しました」と表示していた。|修正済み。状態取得時に外枠（`GetWindowRect`）を記録し、通常表示へ戻すUndoでは配置の復元後に外枠の位置へ合わせる。通常表示の完了判定は見える矩形の一致とした。最大化への復元は従来どおり通常復元位置で比べる。|
|CHN-01|低|管理要求の読取り上限と応答書込み期限がない（[セキュリティ診断](../security-audit-2026-10-15/report.md)）。|修正済み。1要求を改行までの4096文字に制限し、応答書込みにも接続後2秒の期限を設けた。|
|CR-03|低|起動中の既存インスタンスと実行ファイルのパスが違う（ポータブル版とsetup版の併用など）と、後から起動した側は何も表示せずに終了する。|未対応。|
|CR-04|低|プロセス名の取得方法が一覧（`QueryFullProcessImageName`）とドラッグ選択（`Process.ProcessName + ".exe"`）で異なり、表示がずれる場合がある。|未対応。|
|CR-05|低|WGCのサムネイル撮影で1枚ごとにD3D11デバイスを作り直している。|未対応。|
|CR-06|低|テストがprivateメンバー名をリフレクションで参照している。CIがない。|未対応。|
|CR-08|中|表示倍率100%以外（125%で確認）では、文字だけが大きくなり部品が枠からはみ出す。プレビューを開閉すると、折りたたみ時の高さが起動時と変わる（125%で263→318px）。原因は3つ。(1) `AutoScaleMode.Dpi`だけを指定して`AutoScaleDimensions`がなく、構築も`SuspendLayout`/`ResumeLayout`で囲んでいないため、96DPI基準のフォームサイズ・最小サイズ・行列の幅が拡大されていなかった。(2) プレビュー開閉は最小サイズをウィンドウ枠込みで`* DeviceDpi / 96`しており、起動時の値と一致しない。(3) `AutoSize`のボタンは作成時に実際のDPIで大きさが決まり、`GrowOnly`のため拡大がさらに重なる。|修正済み。`MainForm`と`ThumbnailPickerForm`で基準DPIを96とし、構築全体をレイアウト一時停止で囲んだ。ボタンは`GrowAndShrink`にし、幅の下限（既定75px、⌖ 38px、▼ 32px）は`MinimumSize`で保った。プレビュー開閉は、現在の最小サイズに96DPI基準の差分（165px）を拡大して増減する。|
|CR-07|文書|README・ガイド・ZIP同梱の案内が「v0.1.1」「本体からの正式導入は未対応」のまま。「設定・履歴は保持します」と書かれているが、ChunapToolは設定もUndo履歴も保存しない。手順に作者環境の固定パスが残る。テストプロジェクトの版が0.1.1。|修正済み。|

## 検証

- `pwsh -File dev/scripts/test.ps1`: 単体27/27成功。管理連携は、停止ガードに加えて次を追加し成功。
  - 要求の解釈（旧形式・JSON・整数でない期待PID）と、4096文字ちょうど・超過の読取り。
  - 検証専用のpipe名で受付を起動し、整数でない期待PID、上限超過、壊れたJSONの各要求の後も`status`へ応答すること。
- `pwsh -File dev/scripts/test.ps1 -Ui`: UI回帰24/24、サムネイル12/12（表示倍率125%、DPI=120）。
  - 追加した「スナップ中の位置へのUndoは見える位置の一致で完了とする」は成功。完了判定を修正前の式へ一時的に戻すと失敗することも確認した。
  - CR-08の修正前は、プレビュー開閉の高さ復元と最小ウィンドウサイズでの配置の2件が失敗していた（`f0f9a05`でも同じ）。実測では、DPI=120でも行の高さは38px、最小サイズは780×255のままで、高さ30pxの検索欄が高さ32pxの親から下へはみ出していた。修正後は行の高さ48px、最小サイズ970×307となり、2件とも成功する。最小レイアウトの検証には、行の高さが表示倍率に比例することの確認を追加した。
  - テストプロセスだけを互換フラグ（環境変数`__COMPAT_LAYER=DPIUNAWARE`、PC設定は変更しない）で96DPIとして実行しても、UI回帰24/24、サムネイル12/12が成功した。主要13部品の位置・サイズは、修正前の`f0f9a05`と完全に一致した（表示倍率100%の見た目は変わらない）。
- `-Native`（専用テストウィンドウの実機操作）、実際のスナップ配置でのUndo、本体からの管理要求は未実施。CR-02は実機での確認が必要。
