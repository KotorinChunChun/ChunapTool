# ChunapTool v0.2.0 設計書

対応要求: [v0.2.0要求](v0.2.0-req.md)

作成日: 2026-10-31 / 状態: 設計確定（2026-10-31、未決事項Q1〜Q6は案どおりで承認）

## 1. 目的と範囲

競合製品の機能を参考に14機能（R1〜R14）を追加し、既存機能を含む全機能をコマンドラインから呼び出せるようにする。テストはコマンドラインの呼び出しで行う。

ChunapToolの強みは「数値でぴったり合わせる」「100手まで戻せる」「プレビューを見ながら調整できる」点である。ゾーンやスナップによる大まかな配置はWindows標準やPowerToys FancyZonesが強いため、本版は正確さと録画前の準備を伸ばす方向で設計する。

| 要求 | 参考にした製品 |
|---|---|
| R1 サイズのプリセット | Sizer |
| R4 定位置への配置 | Rectangle、Magnet、Windowsのスナップ |
| R5 対象を最前面に固定 | PowerToys Always On Top |
| R6 対象のハイライト | Always On Topの枠表示、Window Spy系ツール |
| R8 モニターの指定 | DisplayFusion（次・前のモニターへ移動） |
| R9 全体ショートカット | DisplayFusion、Rectangle |
| R12 配置プロファイル | PowerToys Workspaces、DisplayFusion Window Position Profiles |
| R13 グリッド配置 | PowerToys FancyZones（簡易版として、作業領域を格子に分ける方式に限定） |
| R14 透明度 | DisplayFusion |

対象外とするもの:

- アプリの起動（R12は、すでに開いているウィンドウを並べ直すだけとする）。
- ドラッグ操作によるゾーン編集の画面、Windowsのスナップ状態の再現。
- 管理者権限で動くウィンドウの操作（UIPIにより拒否されるため、理由を示して失敗とする）。

## 2. 全体構成

```
                ┌───────────────┐   ┌──────────────────────┐
  利用者 ──GUI──▶│ ChunapTool.exe │   │ chunap.exe（新規CLI）  │◀── シェル・スクリプト・テスト
                │  MainForm等    │   │  引数解析・出力・終了コード │
                └──────┬────────┘   └──────────┬───────────┘
                       │  管理pipe v3（gui系コマンド）  │
                       │◀─────────────────────────────┘
                       ▼                                ▼
              ┌─────────────────────────────────────────────┐
              │ Operations（新規）: 対象指定・操作・反映確認・結果  │
              ├─────────────────────────────────────────────┤
              │ Core: 座標計算・履歴・設定・配置プロファイルの照合     │
              │ Native: Win32/DWM/WGC、オーバーレイ、ホットキー       │
              └─────────────────────────────────────────────┘
```

### 2.1 プロジェクト

| プロジェクト | 出力 | 内容 |
|---|---|---|
| `src/ChunapTool`（既存） | `ChunapTool.exe`（WinExe） | GUI、Core、Native、Operations、管理pipe |
| `src/ChunapTool.Cli`（新規） | `chunap.exe`（コンソール） | 引数解析、出力、終了コード。`src/ChunapTool`をProjectReferenceで参照する |
| `tests/ChunapTool.Tests`（既存） | `ChunapTool.Tests.exe` | 既存の検証に、CLIの検証（`--cli`系）と確認用ウィンドウの拡張を追加 |

CLIを別の実行ファイルにする理由: WinExeは、シェルから実行したときに終了を待たれず、標準出力も扱いにくい。スクリプトやテストが終了コードとJSONを確実に受け取れるよう、コンソールアプリとして分ける。外部パッケージは追加しない（引数解析も自前で書く。セキュリティ診断の「外部PackageReferenceなし」を維持する）。

### 2.2 Operations層（新規）

現在`MainForm.MutateAsync`にある「要求を送る → 70ms間隔で状態を読む → 2回続けて変化がなく、完了条件を満たしたら確定 → 1.8秒で打ち切る」という流れを、`WindowOperations`へ切り出す。GUI、CLI、管理pipeはすべてこの層を通す。

```csharp
internal sealed class WindowOperations(IWindowService windows, IClock clock)
{
    Task<OperationResult> SetBoundsAsync(WindowIdentity target, BoundsRequest request, OperationOptions options);
    Task<OperationResult> ArrangeAsync(WindowIdentity target, ArrangePosition position, OperationOptions options);
    Task<OperationResult> SetGridAsync(WindowIdentity target, GridCell cell, OperationOptions options);
    Task<OperationResult> MoveToMonitorAsync(WindowIdentity target, MonitorChoice monitor, OperationOptions options);
    Task<OperationResult> SetMaximizedAsync(WindowIdentity target, bool maximized, OperationOptions options);
    Task<OperationResult> SetTopMostAsync(WindowIdentity target, bool? topMost, OperationOptions options);
    Task<OperationResult> SetOpacityAsync(WindowIdentity target, int? percent, OperationOptions options);
    Task<OperationResult> RestoreAsync(WindowIdentity target, WindowState state, OperationOptions options);
}

// DryRunでは計算結果だけを返し、対象へ要求を送らない。
record OperationOptions(bool AllowOutside, BoundsBasis Basis, bool KeepAspect, bool DryRun, TimeSpan Timeout);
record OperationResult(WindowState Before, WindowState? After, WindowRequest Requested, OperationStatus Status, IReadOnlyList<string> Warnings);
```

履歴（Undo/Redo）はGUIのプロセスが持つ。CLIで直接操作した結果は履歴に入らない。その代わり、すべての操作結果に変更前の状態（`before`）を含めるので、`chunap restore --from <ファイル>`で戻せる。GUIの履歴に入れたい場合は`--via-gui`を付ける（7章）。

## 3. 共通の仕組み

### 3.1 対象の指定（セレクター）

CLIと管理pipeは、次の条件を組み合わせて（AND）対象を決める。

| オプション | 意味 |
|---|---|
| `--hwnd <10進数または0x16進数>` | ウィンドウハンドル |
| `--pid <番号>` | プロセスID |
| `--title <文字列>` | タイトルの部分一致（大文字小文字を区別しない） |
| `--title-exact <文字列>` | タイトルの完全一致 |
| `--process <名前.exe>` | 実行ファイル名（`GetProcessName`と同じ取得方法） |
| `--class <クラス名>` | ウィンドウクラス名 |
| `--at <x,y>` | 画面座標にあるトップレベルウィンドウ（GUIのドラッグ選択と同じ判定） |
| `--foreground` | 前面ウィンドウ |
| `--gui-target` | 起動中のGUIが現在選んでいる対象 |

- 候補になるのは、既存の一覧と同じ条件（表示中、タイトルあり、クローク（非表示化）されていない）を満たすウィンドウに限る。ChunapTool.exeとchunap.exeのウィンドウは除外する。
- 一致が0件なら終了コード3、2件以上なら終了コード4とし、候補の一覧を出力して操作しない。順番で選ぶオプションは設けない（実行のたびに順番が変わりうるため）。
- 解決した対象は、HWNDとPIDの組（`WindowIdentity`）で保持する。操作の直前にも照合する（既存の`Matches`）。

### 3.2 安全規則

- 一意に決まらない対象は操作しない。`--dry-run`は計算結果だけを出力し、変更しない。
- 対象アプリが応答しない場合（`SendMessageTimeout`で200ms以内に応答しない場合）や、権限が不足する場合は、要求を送らずに終了コード5とする。
- 透明度の下限は20%（見えなくなって戻せなくなる事故を防ぐ）。
- テスト用のインスタンスは`--instance <ID>`で分離する（3.4節）。利用者が普段使っているChunapToolには触れない。

### 3.3 設定ファイル（R7）

- 保存先: 既定は`%LOCALAPPDATA%\KotorinToys\ChunapTool\settings.json`。`--settings-dir <フォルダー>`で変更できる（KotorinToysの検証用起動と同じ考え方）。既定の場所は未決事項Q2。
- 書き込みは一時ファイルへ書いてから置き換える。読み込みに失敗した場合は、壊れたファイルを`settings.json.broken-<日時>`へ退避し、既定値で起動して警告を出す（CLIは終了コード8）。
- GUIは起動時に読み込み、変更するたびに保存する。CLIで変更した場合は、管理pipeの`reload-settings`でGUIへ反映する。CLIの`config set`は、GUIが起動中なら自動で`reload-settings`を送る。

```json
{
  "schemaVersion": 1,
  "gui": { "autoRead": true, "autoApply": true, "allowOutside": false, "toolTopMost": true,
           "basis": "frame", "keepAspect": false, "monitorRelative": false, "previewExpanded": false },
  "presets": [ { "name": "FHD", "width": 1920, "height": 1080, "basis": "client" } ],
  "layouts": [ { "name": "録画", "entries": [ /* 4.12節 */ ] } ],
  "hotkeys": [ { "keys": "Ctrl+Alt+1", "action": "preset", "argument": "FHD", "target": "foreground" } ]
}
```

文書の「設定・Undo履歴は保存しない」という記述は、「設定は保存し、Undo履歴は保存しない」へ改める。

### 3.4 インスタンスの分離

現在、GUIのミューテックス名`Local\ChunapTool`と管理pipe名`KotorinToys.<SID>.chunap-tool`は固定である。`ChunapTool.exe --instance <ID>`と`chunap --instance <ID>`を追加し、両方の名前に`<ID>`を付ける。省略時は従来と同じ名前とし、KotorinToys本体との互換を保つ。テストでは毎回`test-<GUID>`を使う。

## 4. 機能別の設計

### 4.1 R1 サイズのプリセット

- モデル: `Preset(Name, Width, Height, Basis)`。既定値は、FHD 1920×1080、HD 1280×720、720×1280（縦長）、1024×768、800×600。基準はいずれもclient。
- 適用すると位置は変えずにサイズだけ変える。そのうえで、画面外可がOFFなら作業領域へ収める。
- GUI: 座標欄の行に「プリセット▼」を置き、選ぶと即座に反映する。「プリセットの管理…」の画面で追加・削除・並べ替え・名前の変更ができる。
- CLI: `chunap preset list|add|remove|rename|move|apply`。

### 4.2 R2 見える枠とクライアント領域の切り替え

- `WindowState`にクライアント領域の画面座標`ClientBounds`（`GetClientRect`と`ClientToScreen`で求める）を追加する。
- クライアント基準で指定された場合は、見える枠とクライアント領域の差（左右上下の4辺）を現在の状態から求めて、見える枠に換算する。換算後は、既存の見える枠基準の処理（不可視枠の補正を含む）に渡す。
- 作業領域への制限は常に見える枠で判定する。サイズを縮めた場合は、クライアント基準の値へ戻して表示する。
- GUI: 座標欄の左に「基準：枠｜中身」の切替を置く。X/Y/W/Hの表示は、選んだ基準の値にする。
- CLI: `--basis frame|client`（`get`、`set`、`preset`など）。

### 4.3 R3 縦横比の固定

- Coreの純粋関数`AspectRatio.Fit(int? width, int? height, double ratio)`で計算し、四捨五入する。最小サイズ（32）を満たさない場合は、もう一方の辺から逆算する。
- 比率の元は、固定をONにした時点の対象のサイズ。プリセットを選んだ場合は、そのプリセットの比率とする。
- GUI: 「比率固定」のチェック。WとHのどちらかを編集すると、もう一方を自動で更新する。
- CLI: `set --width 1600 --keep-aspect`。比率は対象の現在のサイズから求める。`--aspect 16:9`で明示もできる。

### 4.4 R4 定位置への配置

- Coreの`WindowGeometry.Arrange(position, current, workArea)`で計算する。対象が属するモニター（`MonitorFromWindow`、NEAREST）の作業領域を使う。
- 指定できる位置: `center`、`left`、`right`、`top`、`bottom`、`top-left`、`top-right`、`bottom-left`、`bottom-right`、`fill`。
  - 半分の位置（`left`など）は作業領域の半分に合わせる。幅が奇数の場合は、左側を切り捨て、右側に余りを足して隙間を作らない。
  - 中央と四隅（`center`、`top-left`など）はサイズを保ち、位置だけ動かす。
- 最大化中の場合は、通常表示に戻してから配置する（1回の操作として履歴に入れる）。
- GUI: 「配置▼」メニュー。CLI: `chunap arrange <位置>`。

### 4.5 R13 グリッド配置

- 作業領域を列C×行R（1〜12）に分け、セル(c, r)から幅w、高さhのセル分を占める範囲を求める。境界を`area.X + area.Width * i / C`の整数計算で決め、隙間や重なりが出ないようにする。
- GUI: 「配置▼」の中に「グリッド…」を置く。小さな格子の画面でセルをドラッグして範囲を選ぶ。
- CLI: `chunap grid --size 3x2 --cell 0,0 [--span 2x1]`。

### 4.6 R8 モニターの指定

- Nativeに`EnumerateMonitors()`を追加する（`EnumDisplayMonitors`、`GetMonitorInfoW`（デバイス名を取得）、`GetDpiForMonitor`）。番号は1から始め、左上の座標が小さい順（X、Yの順）に付ける。
- 移動するときは、元の作業領域内の相対位置（左上の比率）を保つ。サイズは、移動先の作業領域に収まる範囲で保つ。
- 表示倍率が違うモニターへ移すと、DPIに対応したアプリは自分でサイズを変える。既定（`--size keep-logical`）では、アプリが変えたサイズをそのまま受け入れ、位置だけを合わせ直す。`--size keep-pixels`では、要求したピクセル数を1回だけ再適用する。
- モニター基準の座標: 作業領域の左上を(0, 0)とした値で表示・入力する。
- GUI: 「モニター▼」（番号・解像度・倍率）と「モニター基準」のチェック。CLI: `chunap monitors`、`chunap move-monitor next|prev|<番号>`、`set --monitor <番号> --relative`。

### 4.7 R5 対象を最前面に固定

- 状態は`GWL_EXSTYLE`の`WS_EX_TOPMOST`で読む。変更は`SetWindowPos(HWND_TOPMOST/NOTOPMOST, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE|SWP_ASYNCWINDOWPOS)`で行う。
- `WindowState`に`IsTopMost`を追加し、履歴の比較と復元の対象に含める（戻すと最前面の状態も戻る）。
- アプリ自身が最前面を解除する場合があるため、結果は必ず読み直して報告する。
- GUI: 「対象を最前面」のチェック（ChunapTool自身の「最前面」とは別）。CLI: `chunap topmost on|off|toggle`。

### 4.8 R14 透明度

- 対象に`WS_EX_LAYERED`がなければ付けて、`SetLayeredWindowAttributes(LWA_ALPHA)`で透明度を設定する。自分で付けたことは、ウィンドウのプロパティ（`SetProp`、名前`KotorinToys.ChunapTool.AddedLayered`）に記録する。
- 元から`WS_EX_LAYERED`を持ち、`GetLayeredWindowAttributes`で値を読めないウィンドウ（`UpdateLayeredWindow`で自分で描画しているもの）は、表示が崩れるおそれがあるため拒否する。
- 範囲は20〜100%。100%への解除（`reset`）では、自分で付けた`WS_EX_LAYERED`だけを外す。
- `WindowState`に`OpacityPercent`を追加し、履歴の対象に含める。ChunapToolを終了しても自動では戻さない（「終了時に対象ウィンドウを自動復元しない」という既存の方針に合わせる）。
- GUI: 「透明度▼」（100/90/80/70/50%）。CLI: `chunap opacity <20-100>|reset`。

### 4.9 R6 ハイライト

- 透明で、クリックを素通しする最前面のオーバーレイを表示する（`WS_EX_LAYERED|WS_EX_TRANSPARENT|WS_EX_TOOLWINDOW|WS_EX_TOPMOST|WS_EX_NOACTIVATE`）。見える枠の外側に、太さ4px（DPIに比例）の枠を描き、2回点滅させて消す（既定1.2秒）。
- GUIで対象を選んだときに自動で表示する（設定でOFFにできる）。
- 表示は、呼び出したプロセス（GUIまたはCLI）が行う。CLIは表示が終わってから終了する。前面化はせず、入力も奪わない。
- CLI: `chunap highlight [--duration <ミリ秒>]`。JSONで、描いた矩形とオーバーレイのHWNDを返す（テストで照合するため）。

### 4.10 R10 やり直し（Redo）

- `WindowHistory`にやり直し用の履歴を追加する。`AcceptUndo`のときに、戻す前の状態をやり直し用の履歴へ積む。Undo・Redo以外の新しい変化を観測したら、やり直し用の履歴を消す。
- Undoと同じく、取り出し（`TryPeekRedo`）と確定（`AcceptRedo`）を分け、復元に失敗しても履歴を消費しない。
- GUI: 「戻す」の右に「やり直す」を置き、Ctrl+Z／Ctrl+Yにも割り当てる。CLI: `chunap gui redo`。

### 4.11 R9 全体ショートカット

- GUIのプロセスが`RegisterHotKey`で登録する。そのため、GUIが起動している（常駐の`--startup`を含む）間だけ有効。既定では何も割り当てない（他のアプリとの衝突を避ける）。
- 割り当てられる操作: `preset:<名前>`、`arrange:<位置>`、`grid:<CxR>:<c,r>[:<wxh>]`、`move-monitor:next|prev`、`topmost:toggle`、`opacity:<値>`、`highlight`、`undo`、`redo`。
- 対象は、前面ウィンドウ（既定）か、GUIが現在選んでいる対象。前面ウィンドウを操作した場合は、それをGUIの現在の対象にしてから操作する。そのため、戻す・やり直すがそのまま使え、履歴の仕組みも変えずに済む。
- 登録に失敗した組み合わせ（他のアプリが使用中など）は、`hotkey list`と画面で「登録失敗」と示す。
- KotorinToysの`shortcuts`要求に、実際に有効なキーを返すよう実装する（`ManagementEndpoint`には受け口が既にある）。`config/shortcuts.json`の扱いは未決事項Q5。
- GUI: 「ショートカット設定…」の画面（キーの記録、操作・対象の選択）。CLI: `chunap hotkey list [--effective]|set|remove`、テスト用の`chunap gui hotkey-invoke <キー>`。

### 4.12 R12 配置プロファイル

- 保存する項目（1ウィンドウごと）: プロセス名、クラス名、保存時のタイトル、見える枠、最大化の有無、最前面、透明度、モニターのデバイス名と、作業領域内の相対的な矩形。
- 復元の照合: プロセス名とクラス名で候補を絞る。そのうえで、タイトルの完全一致 → 部分一致（保存時のタイトルを含む） → 候補が1件だけ、の順に照合する。それでも一意に決まらない項目は、飛ばして「曖昧」と報告する。同じウィンドウを2つの項目に割り当てない。
- 保存時のモニターがない場合は、メインモニターの同じ相対位置に置き、警告を出す。
- 復元は1件ずつ反映を確認しながら行い、項目ごとの結果（適用・飛ばし・失敗と理由）を返す。
- GUI: 「配置プロファイル▼」（現在の対象を追加、一覧中のウィンドウを保存、復元、管理）。CLI: `chunap layout list|show|save|add|remove|restore`。保存の対象は`--all`（候補すべて）、`--filter <文字列>`、またはセレクターで選ぶ。

### 4.13 R11 外部からの適用

コマンドライン（5章）と管理pipe v3（7章）で実現する。どの操作も`--via-gui`を付けるとGUIを経由し、GUIの履歴に入る。

## 5. コマンドライン仕様

### 5.1 書式

```
chunap <コマンド> [サブコマンド] [セレクター] [オプション]
共通: --json  --dry-run  --timeout <ミリ秒（既定3000）>  --settings-dir <フォルダー>  --instance <ID>  --via-gui
```

出力の既定は日本語の文章で、`--json`ではUTF-8のJSONを1件出力する。`chunap help [コマンド]`で使い方を表示する。

### 5.2 コマンド一覧（全機能との対応）

| 機能 | コマンド | GUIでの対応 |
|---|---|---|
| 候補の一覧・検索 | `list [--filter <文字列>]` | 検索欄・対象コンボ |
| ドラッグ選択 | `pick --at <x,y>` | ⌖ドラッグ |
| 状態の取得 | `get <セレクター> [--basis]` | X/Y/W/H、最大化表示 |
| 位置・サイズ変更 | `set <セレクター> [--x] [--y] [--width] [--height] [--basis] [--keep-aspect\|--aspect W:H] [--allow-outside] [--monitor N --relative]` | 座標欄・適用・自動反映 |
| 最大化・通常化 | `maximize` / `unmaximize` | 最大化／通常化 |
| 画面内補正 | `constrain` | 画面外可OFFの自動補正 |
| 状態の復元 | `restore --from <JSON>` | 戻す（GUI履歴は`gui undo`） |
| R1 プリセット | `preset list\|add\|remove\|rename\|move\|apply` | プリセット▼ |
| R4 定位置 | `arrange <位置>` | 配置▼ |

### 5.3 出力（`--json`）

```json
{
  "ok": true, "command": "set", "dryRun": false,
  "target": { "hwnd": "0x1A2B3C", "pid": 1234, "process": "obs64.exe", "title": "OBS 30.2" },
  "before": { "frame": {"x":0,"y":0,"width":1280,"height":760}, "client": {...}, "outer": {...},
              "maximized": false, "minimized": false, "topMost": false, "opacity": 100,
              "monitor": {"index":1,"device":"\\\\.\\DISPLAY1","dpi":120}, "placement": {...} },
  "requested": { "basis": "client", "width": 1280, "height": 720 },
  "after": { ... },
  "warnings": []
}
```

失敗時は`{"ok": false, "error": {"code": "ambiguous-target", "message": "...", "candidates": [...]}}`とする。`before`はそのまま`restore --from`に渡せる。

### 5.4 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | その他の失敗 |
| 2 | 引数の誤り |
| 3 | 対象が見つからない |
| 4 | 対象が一意に決まらない |
| 5 | 対象が応答しない・権限不足・拒否（透明度の非対応など） |
| 6 | GUIが起動していない・応答しない |
| 7 | 反映を確認できない（タイムアウト） |
| 8 | 設定ファイルの不正 |

### 5.5 使用例

```powershell
# OBSの中身を1280×720にし、モニター1の中央へ
chunap set --process obs64.exe --basis client --width 1280 --height 720
chunap arrange center --process obs64.exe

# 変更前の状態を保存しておき、あとで戻す
chunap get --title "動作確認用" --json > before.json
chunap restore --title "動作確認用" --from before.json
```

## 6. GUIの変更

- 2行目の下に、操作行を1行追加する: 「基準 枠｜中身」「比率固定」「プリセット▼」「配置▼」「モニター▼」「対象を最前面」「透明度▼」。
- 「戻す」の右に「やり直す」を置く。
- 「その他▼」に次をまとめる: ハイライト、グリッド…、配置プロファイル、プリセットの管理…、ショートカット設定…、設定フォルダーを開く。
- 追加する画面: `PresetEditorForm`、`GridPickerForm`、`LayoutManagerForm`、`HotkeyEditorForm`。すべて`BrandedForm`と`WindowTitle.Create`を使い、`AutoScaleDimensions`は96DPIとする（v0.1.2で修正したDPI対応の方式に合わせる）。
- 最小ウィンドウサイズは、追加する行の分だけ大きくする。最小レイアウトの検証（重なり、はみ出し、表示倍率への比例）の対象に、追加した部品も含める。

## 7. 管理pipe v3

- 既存の`status`、`show`、`stop`、`shortcuts`はそのまま残す。応答の`protocolVersion`は3とし、`capabilities`に`invoke`を追加する。
- 要求の形式: `{"command":"invoke","requestId":"...","expectedPid":123,"action":"apply","args":{...}}`。応答には`data`（5.3節と同じ結果）を加える。
- `invoke`で使える`action`: `select`、`get`、`apply`、`maximize`、`arrange`、`grid`、`move-monitor`、`preset`、`topmost`、`opacity`、`highlight`、`undo`、`redo`、`option`、`preview`、`thumbnails`、`hotkey-invoke`、`reload-settings`。
- 1要求の上限（4096文字）は維持する。配置プロファイルのような大きなデータはpipeで送らず、設定ファイルを経由する。
- 反映の確認に時間がかかるため、`invoke`だけ応答の期限を`args.timeout`（上限10秒）まで延ばす。その他の要求は従来どおり2秒とする。
- 処理中（`busy`）やモーダル画面の表示中は、既存の停止ガードと同様に`refused`を返す。

## 8. テスト設計

### 8.1 層と実行場所

| 層 | 起動方法 | 内容 | 実行場所 |
|---|---|---|---|
| Core単体（既存を拡張） | `test.ps1` | 配置・グリッド・比率・モニター基準の計算、セレクターの照合、Redo、設定の読み書き、配置プロファイルの照合 | ローカル、CI |
| 不可視UI回帰（既存を拡張） | `test.ps1 -Ui` | 追加した部品の配置、偽サービスでのGUI操作 | ローカル、CI |
| CLI論理 | `test.ps1 -Cli` | 引数の誤り（終了コード2）、`help`、`config`・`preset`・`hotkey`・`layout`の設定操作（一時フォルダーの`--settings-dir`）、壊れた設定（終了コード8） | ローカル、CI |
| CLI実機 | `test.ps1 -CliNative` | 確認用ウィンドウに対する全操作と`--dry-run`、セレクターの一意性（終了コード3・4）、`restore` | ローカル（CIは試行のうえで判断） |
| CLI-GUI | `test.ps1 -CliGui` | `--passive --instance test-<GUID>`で起動したGUIを、`chunap gui …`で操作する。Undo/Redo、`--via-gui`、`reload-settings`、`hotkey-invoke`、停止ガード | ローカル（CIは試行のうえで判断） |

テストは`chunap.exe`を別プロセスとして起動し、終了コードとJSONで判定する。各ケースは、ログに記録したコマンドをそのまま手で実行して再現できる。ログは`dev/history/v0.2.0/logs/<RunId>/`に保存する。

### 8.2 確認用ウィンドウの拡張

`ChunapTool.Tests.exe --fixture`に次を追加し、テストごとに条件の違うウィンドウを起動できるようにする。

```
--fixture --title <一意の名前> --client <幅x高さ> --position <x,y> [--min <幅x高さ>] [--layered-by-app] [--hung <ミリ秒>]
```

`--layered-by-app`は透明度の拒否、`--hung`は応答なし（終了コード5）の検証に使う。

### 8.3 自己確認にしない工夫

CLIの`get`だけで結果を確かめると、CLI自身の誤りを見逃すおそれがある。そのため、テストのランナーは別の経路でも照合する。具体的には、Win32を直接呼んでDWMの枠、クライアント矩形、`WS_EX_TOPMOST`、透明度を読み、CLIのJSONと突き合わせる。

### 8.4 主なテストケース

| 要求 | ケース |
|---|---|
| C3 | 同じタイトルの確認用ウィンドウを2つ起動すると終了コード4になり、どちらも動かない。存在しない対象は終了コード3。`--dry-run`では状態が変わらない |
| R1 | `preset add/apply`で、client基準の1280×720が実測と一致する。存在しないプリセットは終了コード2 |
| R2 | 同じ要求をframe基準とclient基準で出し、差が枠の太さと一致する |
| R3 | `--keep-aspect`で16:9を保つ。最小サイズで逆算する |
| R4・R13 | 全位置と、3×2格子の全セルで、隙間・重なりがない（作業領域の和と一致する） |
| R8 | 1モニターの環境では、`next`が同じモニターへの移動になり変化しないことを確認する。複数モニターの環境ではモニター間の移動を確認する（そうでない環境では飛ばして報告する） |
| R5・R14 | ON・OFF・トグル、20%未満の拒否、`--layered-by-app`の拒否、`reset`で`WS_EX_LAYERED`が外れる |
| R6 | 返されたオーバーレイの矩形が、見える枠と枠の太さから計算した値と一致し、指定時間後に消える |
| R7 | GUIで変えた設定がファイルに保存され、`--settings-dir`を変えると独立する |
| R9 | `hotkey set`、`gui hotkey-invoke`で操作を実行する。登録済みのキーと衝突すると「登録失敗」と表示される |
| R10 | 移動 → `gui undo` → `gui redo`で元へ戻る。新しい移動でやり直し用の履歴が消える |
| R12 | 確認用ウィンドウを3つ保存・移動・復元する。1つを閉じた場合は飛ばして報告する。同名を増やした場合は「曖昧」と報告する |
| 既存 | `list`、`pick`、`maximize`、`constrain`、`capture`（専用フォームのWGC撮影）、`gui status/show/stop` |

実機のマウス・キーボード入力は使わない。全体ショートカットは`hotkey-invoke`で検証し、実際のキー押下での確認は手動確認の項目とする。

## 9. 配布と互換性

- `package.ps1`は2つのプロジェクトを同じフォルダーへ発行し、`chunap.exe`の存在と版を検査する。インストーラーにも含める。
- PATHは変更しない（PCの環境を変えないため）。文書では、インストール先のフルパスで呼び出す例を示す。
- `tool.json`の`capabilities`に`invoke`を追加し、R9を実装した時点で`shortcuts`も追加する。
- 管理pipeは、既存の要求と応答の形を維持する（KotorinToys本体との互換）。

## 11. リスク

- 他のアプリの挙動: 自分でサイズや最前面を戻すアプリがある。結果は必ず読み直して報告し、確認できなければ終了コード7とする。
- 表示倍率の違うモニター間の移動: アプリ側のDPI対応によって結果が変わる。4.6節の2つの方式で吸収する。
- 透明度: 描画方式によっては表示が崩れる。描画方式を判定して拒否し、自分で付けた属性だけを外す。
- CIの描画環境: GitHub Actionsでウィンドウを使うテストが安定するかは未確認。CLI実機とCLI-GUIのテストは、まずローカルで行う。
