## 2. P1の実装

| 項目 | 実装 |
|---|---|
| 操作層 | `Operations/WindowOperations.cs`。`MainForm.MutateAsync`の反映確認（70ms間隔、2回安定で確定、期限で打切り）を`WaitForAsync`として切り出し、GUIとCLIで共有する。完了条件（位置・サイズ、最大化、復元）も同じ関数を使う。GUIの画面を閉じた場合の打切りは、`OperationCanceledException`で扱う |
| 対象指定 | `Core/TargetSelector.cs`（純粋関数）。`WindowEntry`にクラス名、`IWindowService`に前面ウィンドウの取得を追加。ChunapTool.exeとchunap.exeは除外する |
| CLI | `src/ChunapTool.Cli`（`chunap.exe`、外部パッケージなし）。`list`、`pick`、`get`、`set`、`maximize`、`unmaximize`、`constrain`、`restore`、`version`、`help`。起動時にPer-Monitor V2にして、GUIと同じ物理ピクセルで扱う |
| 引数の安全 | すべての引数を読み取って検査してから、対象の解決と変更を行う。綴り誤りのオプション（例: `--wdith`）や、値の書き忘れ（`--pid --json`）で対象を動かさない |
| 出力 | `--json`は既定のエンコーダーで非ASCIIを`\uXXXX`にし、コンソールのコードページに依存させない。変更系は`before`・`requested`・`after`・`warnings`を返す。`get`の`state`と変更系の`before`は、`restore --from`でそのまま読める |
| `--instance` | `ChunapTool.exe --instance <ID>`で、ミューテックス名と管理pipe名に`<ID>`を付ける。省略時は従来と同じ名前（KotorinToys本体との互換） |
| 確認用ウィンドウ | `--fixture`に`--title`、`--client`、`--position`、`--min`、`--topmost`、`--hung`（UIスレッドを止める）、`--locked`（移動・サイズ変更を無視）を追加 |
| CLI検証 | `ChunapTool.Tests.exe --cli`（ウィンドウを変更しない）と`--cli-native`（確認用ウィンドウと検証用GUIだけを操作）。`test.ps1 -Cli`・`-CliNative`。結果は終了コードとJSONで判定し、位置・最大化はWin32で直接読んだ値とも突き合わせる |
| CI | `-Cli`をGitHub Actionsに追加。`-CliNative`はローカルで実行する |

設計からの変更:

- 設計書2.2節の`WindowOperations`の公開メソッドは、P1で使う`SetBoundsAsync`、`SetMaximizedAsync`、`RestoreAsync`と、共通の`WaitForAsync`・完了条件から作った。GUIは、履歴と画面の更新を`MainForm`に残したまま、反映確認と完了条件を共有する。その他の操作は各フェーズで追加する。
- `--instance`は設計ではP5の項目だが、検証用GUIを利用者のGUIと分離する土台としてP1で実装した。

## 4. P2の実装

| 項目 | 実装 |
|---|---|
| 設定（R7） | `Core/AppSettings.cs`。`SettingsStore`は一時ファイルから置き換えて保存し、変更は毎回ファイルを読み直してから行う（`Update`）。`SettingsDocument`は元のJSONを保持し、未対応の項目（後の版の`layouts`、`gui.monitorRelative`など）を消さない。`presets`がない場合だけ既定のプリセットとし、空の配列は「すべて削除した」として保つ |
| 読めない設定 | GUIは`settings.json.broken-<日時>`へ退避し、既定値で起動して画面下に理由を表示する。CLIは終了コード8で、ファイルを変更しない（`config reset`だけが退避して作り直す）。`schemaVersion`が新しい設定は、GUI・CLIとも退避も上書きもしない（GUIは既定値で起動し、保存しない） |
| GUIの保存 | 自動読み取り、自動反映、画面外可、最前面、基準、比率固定、プレビューの展開を、変更した項目だけ保存する。CLIで変えた他の項目やプリセットを上書きしない。`ChunapTool.exe --settings-dir`で場所を変えられる |
| プリセット（R1） | `Preset`と`Presets`（追加・削除・名前変更・置換・移動、名前は大文字小文字を区別せず一意、幅・高さ32〜100000、名前は制御文字なしの64文字以内）。適用は位置を変えずサイズだけを変える（`WindowOperations.ApplyPresetAsync`） |
| 中身の基準（R2） | `WindowState.ClientBounds`（`GetClientRect`と`ClientToScreen`、最小化中はnull）。`BoundsBases.ToFrame`・`FromFrame`で、見える枠との4辺の差を使って換算する。作業領域への制限は見える枠で判定する |
| 比率固定（R3） | `AspectRatio.Fit`（四捨五入、最小サイズ未満の辺は他方から逆算）と`Shrink`（作業領域に収めるときも比率を保つ） |
| 計算の共有 | `WindowOperations.Plan`で、要求（基準・比率）から送る見える枠を求める。GUIの適用・プリセット・自動補正とCLIの`set`・`preset apply`が同じ関数を使う |
| CLI | `get --basis`、`set --basis --keep-aspect --aspect`、`preset list\|add\|remove\|rename\|move\|apply`、`config path\|get\|set\|reset`、共通の`--settings-dir`。JSONの状態に`client`、変更系の`requested`に`basis`と送った見える枠（`frame`）を加えた |
| GUI | 座標欄の下に「基準（枠／中身）」「比率固定」「プリセット ▼」の行を追加し、最小サイズを40px大きくした。「プリセット ▼」の中に「プリセットの管理…」（`PresetEditorForm`、96DPI基準）を置く |

設計からの変更:

- `config set`は、GUIへ`reload-settings`を送らない（管理pipe v3はP5）。起動中のGUIには次回の起動から反映される。GUIは項目ごとに読み直して保存するため、CLIの変更を上書きしない。
- 読めない設定は、設計ではCLIでも退避するとしていた。CLIの読み取りでファイルを動かすと、利用者が編集中のファイルを失わせるおそれがあるため、CLIは終了コード8で止め、退避は`config reset`だけで行う。
- `schemaVersion`が新しい設定の扱い（退避も上書きもしない）を追加した。
- 設計6章の操作行のうち、P2では「基準」「比率固定」「プリセット」を置いた。「配置」「モニター」「対象を最前面」「透明度」はP3・P4で同じ行へ加える。「プリセットの管理…」は、「その他▼」（P4）ができるまで「プリセット ▼」の中に置く。
- `gui.monitorRelative`はモニター基準（P3）とともに追加する。

P8へ送る項目: アンインストール時に`%LOCALAPPDATA%\KotorinToys\ChunapTool\`の設定を残すか削除するか（導入と削除の文書、インストーラー）。
