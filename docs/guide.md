# ChunapTool 利用・開発ガイド

## ポータブル版

Windows 11 x64向けのZIPをすべて展開してから`ChunapTool.exe`を起動します。.NET 10ランタイムを同梱しているため、別途ランタイムを導入する必要はありません。Python・FFmpegも不要です。古いバージョンが起動中の場合は終了してから新しいバージョンを起動します。ZIPと同時に配布する`SHA256SUMS.txt`でファイルのハッシュを確認できます。

インストーラー版（`ChunapTool-0.1.2-setup.exe`）とKotorinToys 0.1.2以降の本体からの導入・更新・削除は[導入と削除](install.md)を参照してください。

## 操作

- チェックボックスやボタンにマウスを重ねると、用途や操作方法をツールチップで表示します。最大化／通常化とプレビューの開閉は、現在の状態に合わせた説明へ切り替わります。
- 起動時には対象が選ばれていません。検索した後は対象を自分で選びます。ChunapTool自身は一覧に含みません。
- 検索欄に入力すると、タイトルや実行ファイル名で候補をすぐに絞り込みます。「更新」で候補を再取得します。選んでいる対象が絞り込みの条件に合わなくなっても「対象」の一覧に残ります。検索だけでは操作対象も未適用の値も変わりません。画面下の「候補」の件数には条件に合わない現在の対象を含めません。
- 座標とサイズは、見えるウィンドウ枠を基準にしたピクセル値です。透明なリサイズ枠を内部で補正します。
- 「自動読み取り」がONの場合は、ChunapToolの外で変えた対象の位置・サイズを入力欄に反映します。OFFの場合は入力欄の表示値を保持します。対象を選んだ直後の状態と、操作を指示した結果は取得します。対象が終了したか、最大化しているかは常に確認します。
- 「自動反映」ONではスピン操作や入力確定から約250ms後に反映します。OFFでは未適用の入力値を保持し、「適用」を押したときだけ反映します。Enterや「画面外可」の切替だけでは適用しません。ONへ戻すと保留中の編集を反映します。
- 自動読み取りと自動反映は独立して切り替えられます。いずれも初期値はONです。入力中・未適用の編集値は自動読み取りで上書きしません。
- 位置・サイズの反映中もX/Y/W/H欄の入力先を維持します。Enter後は同じ欄、Tab／Shift+Tabでは次／前の欄へ移動できます。反映確認中に続けて入力した値も保持し、自動反映ONなら確認終了後に自動反映、OFFなら次の「適用」で反映します。
- 「画面外可」は適用ボタンの右にあります。OFFでは適用時に、対象が現在属するモニターの作業領域（タスクバーを除く）へ収めます。別モニターへ数値指定で移す際はONにしてください。ONでも要求サイズの最小値は32pxです。定期的な自動補正は自動反映ONの場合だけ行います。
- 通常表示ではボタンを「最大化」、最大化中は「通常化」と表示します。対象アプリ側での最大化やUndoにも追従します。
- 最大化中・最小化中は座標編集を停止します。対象アプリ自身の最小／最大サイズ制限が優先され、実際に反映された値を再取得します。
- 「戻す」で最大100手まで戻せます。ChunapToolの外でドラッグした操作も履歴に含まれます。別の対象を選ぶと履歴をリセットします。操作に失敗しても履歴は消費しません。
- スナップ（画面端への吸着）で配置した状態へ戻す場合も、記録した見える位置・サイズへ戻します。Windows上のスナップ状態そのものは復元しません。戻した位置が記録と一致しない場合は成功とせず、画面下へ理由を表示します。（v0.1.3から）
- 「最前面」はこのツールの表示順だけを切り替えます。対象を操作しても対象を手前へ持ってきません。
- 終了時に対象ウィンドウを自動復元しません。必要なら閉じる前に「戻す」を使用してください。

### サイズ合わせ（v0.1.3から）

座標欄の下の行で、録画や配信の前にサイズを合わせる操作をします。

- 「基準」: 「枠」は見えるウィンドウ枠、「中身」はタイトルバーと枠を除いたクライアント領域です。X/Y/W/Hは選んだ基準の値で表示・入力します。どちらの基準でも、作業領域に収まるかは見える枠で判定します。基準を切り替えると、未適用の入力値は同じ位置・サイズを指すように換算します。
- 「比率固定」: ONにした時点の対象の縦横比を保ち、WかHを編集するともう一方を自動で更新します。作業領域へ収めるために縮める場合も比率を保ちます。対象を切り替えると、新しい対象の比率にします。
- 「プリセット ▼」: 登録したサイズを選ぶと、位置を変えずにサイズだけを反映します（Undoできます）。既定はFHD 1920×1080、HD 1280×720、縦長 720×1280、1024×768、800×600で、いずれも中身の基準です。比率固定中に選ぶと、そのプリセットの比率に切り替えます。
- 「プリセットの管理…」: プリセットの追加・変更・削除や並べ替えができます。名前は重複できません。大文字と小文字だけが異なる名前も重複に当たります。幅・高さは32〜100000です。

### 設定の保存（v0.1.3から）

自動読み取り、自動反映、画面外可、最前面、基準、比率固定、プレビューの展開と、プリセットを`%LOCALAPPDATA%\KotorinToys\ChunapTool\settings.json`へ保存し、次回の起動で復元します。Undo履歴は保存しません。

- 設定を変更するたびに項目ごとに保存します。保存前にファイルを読み直すので、コマンドラインで変えた他の項目を上書きしません。起動中にコマンドラインから設定を変えた場合、その変更が画面に反映されるのは次回の起動時です。
- `ChunapTool.exe --settings-dir <フォルダー>`で、別の場所の設定を使えます。
- 設定ファイルを読み込めないときは`settings.json.broken-<日時>`へ退避し、既定値で起動して画面下に理由を表示します。新しいバージョンで作られた設定は退避も上書きもせず、既定値で起動して保存しません。

## プレビュー

初期状態ではプレビューを折りたたんでいます。Xラベル左の「▼」で展開し、「▲」で折りたたみます。折りたたむとDWM登録を解除してプレビュー処理を止め、画面も小さくなります。展開し直すと表示領域は直前の高さに戻ります。

WindowsのDWMサムネイルを使い、対象全体を縦横比を維持して表示します。対象が隠れていてもWindowsが提供する描画を表示します。最小化中は案内へ切り替えます。保護コンテンツ、特殊描画、DWMが提供しない画面は黒くなる・更新されない場合があります。

対象が終了したときは編集とプレビューを解除します。アクセス権や応答状態により操作できない場合は画面下へ理由を表示します。

## ターゲットのドラッグ選択

「対象」の一覧の右にある「⌖」をマウスの左ボタンで押し、そのまま対象ウィンドウへドラッグして離します。ドラッグ中は十字カーソルと候補名が表示されます。ボタンを離すと「対象」の一覧と座標欄が切り替わり、ウィンドウ内の部品に落とした場合も、その部品を含むトップレベルウィンドウが選ばれます。

Esc、マウスキャプチャ喪失、自分自身・無効な場所へのドロップでは現在の対象を維持します。選択中は位置・サイズ編集と管理停止を一時的に無効にします。

## サムネイルから対象を選ぶ

「サムネイル選択」を押すと、現在のモニターの作業領域いっぱいに専用画面を開きます。起動時にはこの画面や撮影処理を開始しません。

- 各カードの上に画像、下にウィンドウ名を表示します。長い名前は省略し、マウスを重ねると全文を表示します。現在の対象は青枠です。
- 候補数と画面サイズから列数とカードの高さを調整します。件数が多い場合は縦スクロールします。
- 検索は画像取得を待たず即時に絞り込みます。候補自体は約2秒おきに再取得します。
- 初回は順番に撮影して画像を表示します。その後は画像ごとに約5秒を目安に更新し、一度に撮影するのは1件だけです。画面内の候補を優先し、件数が多い場合や撮影に時間がかかる場合は一巡が長くなります。
- カードをクリック（またはフォーカスしてEnter／Space）すると対象を確定して通常画面へ戻ります。「閉じる」またはEscは対象を変更せずに戻ります。
- 最小化中・取得不可の対象も名前と状態を表示します。保護コンテンツや完全に画面外のウィンドウなどは、Windowsから黒い画像が返る場合があります。対象を自動的に復元・前面化しません。
- 一覧を閉じると撮影を取り消し、画像と取得資源を解放します。画像はメモリ内でのみ保持し、ファイルへ保存しません。

一覧の撮影はWindows Graphics Captureを使用します。Windowsの仕様により撮影対象へ枠が表示される場合があります。通常画面のライブプレビューとは独立した静止画の撮影です。

## コマンドライン（chunap）

v0.1.3で追加したコマンドラインです。ポータブル版では`ChunapTool.exe`と同じフォルダーの`chunap.exe`を使います。ソースからビルドした場合は`src/ChunapTool.Cli/bin/Debug/net10.0-windows10.0.19041.0/chunap.exe`にあります。PATHは変更しないため、フォルダーを指定して実行してください。`chunap help`、`chunap help <コマンド>`で使い方を表示します。

```powershell
chunap list --filter メモ帳
chunap get --process notepad.exe --json > before.json
chunap set --process notepad.exe --x 100 --y 80 --width 1280 --height 720
chunap restore --process notepad.exe --from before.json
chunap set --process obs64.exe --basis client --width 1280 --height 720
chunap set --process obs64.exe --basis client --width 1600 --keep-aspect
chunap preset add 配信 --width 1280 --height 720
chunap preset apply 配信 --process obs64.exe
chunap config set gui.basis client
```

- 現在のコマンド: `list`、`pick`、`get`、`set`、`maximize`、`unmaximize`、`constrain`、`restore`、`preset`、`config`、`version`、`help`。配置・モニター・最前面・透明度・GUIの操作などは、次のv0.2.0で[v0.2.0設計書](../dev/history/v0.2.0/v0.2.0-design.md)の順に追加します。
- 対象は`--hwnd`、`--pid`、`--title`、`--title-exact`、`--process`、`--class`、`--at x,y`、`--foreground`を組み合わせて指定します。一致が0件なら終了コード3、2件以上なら終了コード4で、何も変更しません。ChunapTool自身は対象外です。
- `--json`で結果をJSON形式で出力します。日本語は`\uXXXX`で出力するため、コンソールのコードページに依存しません。変更系のコマンドは変更前（`before`）と変更後（`after`）の状態を返します。
- `--dry-run`は変更せずに結果だけを計算します。オプションの綴りや値が誤っている場合は、対象を探す前に終了コード2で拒否します。
- `set`は、指定しなかった値を現在の値で補い、`--allow-outside`がなければ作業領域へ収めます（GUIの「画面外可」OFFと同じ）。
- `--basis client`（`get`・`set`）は中身（クライアント領域）を基準にします。既定は`frame`（見える枠）です。`get --json`は基準にかかわらず`frame`と`client`の両方を出力します。
- `set --keep-aspect`は現在の縦横比、`--aspect 16:9`は指定の比率を保ちます。幅と高さのどちらか一方だけを指定してください。
- `preset list|add|remove|rename|move|apply`でプリセットを扱います。`preset apply`は位置を変えずにサイズだけを変えます。存在しない名前や重複は終了コード2です。
- `config path|get [キー]|set <キー> <値>|reset`で設定を扱います。キーは`gui.autoRead`、`gui.autoApply`、`gui.allowOutside`、`gui.toolTopMost`、`gui.basis`、`gui.keepAspect`、`gui.previewExpanded`です。`reset`はGUIの項目を既定値へ戻し、プリセットは残します。
- `--settings-dir <フォルダー>`で設定ファイルの場所を変えられます。読めない設定ファイルは終了コード8で、ファイルを変更しません（`config reset`は退避してから作り直します）。
- CLIで直接操作した結果は、GUIの「戻す」の履歴に入りません。`get --json`の出力を保存しておくと、`restore --from`で戻せます。
- 終了コード: 0 成功、1 失敗、2 引数の誤り、3 対象なし、4 対象が複数、5 応答なし・拒否、7 反映を確認できない、8 設定ファイルの不正。

## ビルドとテスト

既にChunapToolを起動している場合は、一度閉じてから新しいバージョンをビルドして起動してください。二重起動では既存の画面を表示するため、古いバージョンを開いたままでは新しい画面に切り替わりません。ポータブル版とインストール版など、別の場所にあるChunapToolが起動している場合は、両方の場所をメッセージで示します。

```powershell
cd <ChunapToolのクローン先>
pwsh -ExecutionPolicy Bypass -File dev/scripts/build.ps1
pwsh -ExecutionPolicy Bypass -File dev/scripts/test.ps1
pwsh -ExecutionPolicy Bypass -File dev/scripts/test.ps1 -Ui
pwsh -ExecutionPolicy Bypass -File dev/scripts/test.ps1 -Native
pwsh -ExecutionPolicy Bypass -File dev/scripts/test.ps1 -Cli
pwsh -ExecutionPolicy Bypass -File dev/scripts/test.ps1 -CliNative
```

通常のテストは座標制約・履歴と管理pipeの要求処理の検証です。`-Ui`は不可視・非アクティブな自フォームと偽サービスで画面状態・配置座標・サムネイル管理を確認し、他の画面へ入力しません。実描画やDWMの検証ではありません。`-Cli`は`chunap.exe`を実行して、引数の検査・終了コード・一覧と、一時フォルダーの設定に対する`preset`・`config`を確かめます（ウィンドウと利用者の設定を変更しません）。`-CliNative`は確認用ウィンドウを起動し、`chunap.exe`で操作した結果を、Win32で直接読んだ値と突き合わせます。`--instance`で分離した検証用のGUIも起動するため、普段使っているChunapToolには触れません。通常のテスト、`-Ui`、`-Cli`は、mainへのpushとプルリクエストでGitHub Actions（`windows-latest`）でも実行します。`-Native`は専用のテストウィンドウを一時的に起動してWin32連携を検証するため、他の画面作業をしていない対話デスクトップで実行してください。手動確認用ウィンドウは次で起動できます。

```powershell
./tests/ChunapTool.Tests/bin/Debug/net10.0-windows10.0.19041.0/ChunapTool.Tests.exe --fixture
```

WGCで実際に画像を取得する検証では、画面内の最背面に置いた非アクティブな専用フォームだけを使用します。Windowsの撮影APIへアクセスできる通常のpwshで、保存先を指定して実行します。

```powershell
./tests/ChunapTool.Tests/bin/Debug/net10.0-windows10.0.19041.0/ChunapTool.Tests.exe --capture-smoke ./dev/history/v0.1.1/logs/manual-capture
```

初回ビルドでは.NET 10 SDKに加えてWindows SDKの.NET参照パッケージを復元します。NuGetへ接続できる環境が必要です。WGCのWinRT／Direct3D処理はソースに含め、別アプリの実行ファイルやPythonには依存しません。

配布ZIPとチェックサムを作成するには次を実行します。ZIPでは`ChunapTool.exe`と`chunap.exe`を同じフォルダーに入れ、両方のバージョンと`chunap version`の応答を確かめます。出力はプロジェクトのバージョンから決めた`dev/history/vX.Y.Z/logs/<RunId>/`に保存し、既存の配布物は上書きしません。GitHubへの公開操作は含みません。

```powershell
pwsh -ExecutionPolicy Bypass -File dev/scripts/package.ps1
```
